CASELOCK Production Architecture & API Specification

1. Cryptographic Security Architecture

Strict isolation principle: Document contents are NEVER written to the blockchain. Documents are encrypted with AES-256-GCM and stored in high-assurance object storage (S3/MinIO/GovCloud). The blockchain ledger records strictly: SHA256(DocPayload) + DocID + VersionID + SignerPubKey + Timestamp + PreviousBlockHash.

2. Core Backend REST API Routes (FastAPI Blueprint)

POST /api/v1/auth/login — JWT generation with Argon2/bcrypt
GET /api/v1/cases — RBAC-filtered cases list
POST /api/v1/documents/upload — AES-256 encryption, SHA-256 hashing & OCR index
POST /api/v1/documents/{id}/sign — ECDSA signing & Hyperledger transaction minting
GET /api/v1/documents/{id}/verify — Realtime SHA-256 verification against ledger
GET /api/v1/ledger/blocks — Append-only chain blocks
POST /api/v1/ledger/verify — Full mathematical chain validation

3. Docker Deployment Specification

# Launch complete production stack:

$ docker compose up --build -d

Containers: caselock-frontend (Vite/Nginx), caselock-backend (FastAPI/Uvicorn), caselock-db (PostgreSQL 16), caselock-storage (MinIO S3).
